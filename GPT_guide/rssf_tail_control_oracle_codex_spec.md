This document defines **one experiment only**:

> Test whether the current fixed RSSF carrier can be made per-image detectable at low distortion when we are allowed to optimize a small, sample-specific control residual over the final four native PNDM scheduler calls.

This is an **oracle feasibility experiment**.

# 1. Motivation

Current `semantic_sign_v2_trajectory` teacher training established two important facts.

## 1.1 Utility can be preserved much better with trajectory-aligned training

The latest teacher checkpoints showed approximately:

| Step | Per-image TPR | Model evidence | CLIP drop | Paired LPIPS |
|---:|---:|---:|---:|---:|
| 100 | 3.1% | 27/32 | 0.0063 | 0.1415 |
| 250 | 3.9% | 29/32 | 0.0054 | 0.1768 |
| 500 | 14.8% | 32/32 | 0.0036 | 0.2277 |
| 1000 | 48.4% | 31/32 | 0.0015 | 0.2543 |
| 1500 | 49.2% | 32/32 | ~0 | 0.2559 |

Compared with the earlier RSSF teacher with LPIPS around 0.4, the trajectory rescue greatly improved quality.

## 1.2 The remaining bottleneck is specifically per-image detectability

Model-level RSSF evidence becomes extremely strong even while per-image TPR remains low.

This suggests:

- the model can learn the global secret-sign bias;
- but a single set of model weights has difficulty making the **minimum sample-specific corrections** required to push most images across `K >= 24` without increasing distortion.

The key question is now:

> Is this low per-image TPR caused by the RSSF carrier itself being perceptually expensive, or by the difficulty of learning sample-specific corrections through one global model?

The oracle experiment must separate these two possibilities.

---

# 2. Core scientific question

For a clean image generated by SD2.1, let the existing native trajectory reach the cached boundary immediately before the final four PNDM calls.

Allow a separate learnable residual for each of those four calls:

\[
\delta_1,\delta_2,\delta_3,\delta_4.
\]

The oracle asks:

\[
\boxed{
\text{Does there exist a small } \delta_{1:4}
\text{ such that the final image has }K\ge24
\text{ while preserving image quality?}
}
\]

If yes for at least ~90% of sampled images at the existing quality gate, then the carrier is likely feasible and the remaining problem is **imprinting / learning the correction in model weights**.

If no, even with this privileged per-image control, then the current per-image RSSF carrier is itself likely too expensive.

# 8. Oracle intervention space

The oracle control acts only on the final four PNDM model-output calls.

For image \(i\), cached clean guided outputs are:

\[
\epsilon^{0}_{i,1},
\epsilon^{0}_{i,2},
\epsilon^{0}_{i,3},
\epsilon^{0}_{i,4}.
\]

Create learnable residuals:

\[
\delta_{i,t}
\in\mathbb R^{4\times64\times64}.
\]

Initialize:

\[
\delta_{i,t}=0.
\]

During replay use:

\[
\boxed{
\epsilon^{oracle}_{i,t}
=
\epsilon^{0}_{i,t}+\delta_{i,t}
}
\]

and feed this value into the **real restored PNDM scheduler**.

Do not optimize pixels directly.

Do not optimize the final image directly.

Do not optimize the final latent directly.

Do not run a custom diffusion equation.

Use the existing PNDM `scheduler.step`.

---

# 9. Why the cached clean output is the correct oracle baseline

This oracle is intentionally a **control-space upper bound**.

The cached outputs have an important property:

\[
\delta_{1:4}=0
\]

must reproduce the original clean final latent exactly.

Therefore the intervention has a precise zero point.

This experiment asks whether small changes to exactly the same control quantities produced by the UNet can make RSSF per-image detectable.

Do **not** rerun the clean UNet on the perturbed oracle trajectory during this feasibility stage.

That would:

- increase compute substantially;
- mix carrier feasibility with state-dependent clean-model dynamics;
- make the diagnostic less isolated.

The later imprinting experiment will address whether a model can learn these controls.

# 15. Quantization-aware detector input

The final verifier in experiments sees ordinary saved images.

A float image whose semantic coordinate is barely above zero can lose a bit after conversion to 8-bit RGB.

Therefore the oracle detector path must be quantization-aware.

Implement a differentiable fake 8-bit quantization using a straight-through estimator.

Conceptually:

```python
def fake_quantize_rgb8_ste(x):
    x = x.clamp(-1, 1)
    y = ((x + 1) * 0.5 * 255.0).round() / 255.0
    y = y * 2.0 - 1.0
    return x + (y - x).detach()
```

Forward value:

```text
exact 8-bit grid
```

Backward:

```text
identity gradient
```

Use:

```text
x_detector = fake_quantize_rgb8_ste(x_oracle)
```

for the semantic detector path.

Use the original float `x_oracle` for differentiable quality losses.

Add a unit test against the actual project PNG save/read path.

The fake-quantized forward tensor must agree with an actual PIL/PNG roundtrip within the expected exact rounding convention.

If Diffusers/PIL uses a slightly different rounding policy, match the actual existing pipeline rather than this pseudocode.

# 16. Dynamic detector loss

Do **not** reuse the historical clean-fixed easiest-24 selection.

The oracle may choose whichever 24 bits are cheapest for that image.

For current oracle coordinates:

\[
r\in\mathbb R^{32}
\]

and secret signs:

\[
s\in\{-1,+1\}^{32},
\]

define signed margins:

\[
m_j=s_jr_j.
\]

Sort descending:

\[
m_{(1)}\ge m_{(2)}\ge\cdots\ge m_{(32)}.
\]

Detection requires:

\[
K\ge24.
\]

Therefore the relevant coordinates are the current top 24 signed margins.

Define:

\[
T=\operatorname{TopK}_{24}(m).
\]

Use a small optimization-only safety margin:

```text
oracle_bit_margin = 0.02
```

Then:

\[
\boxed{
L_{det}
=
\frac1{24}
\sum_{u\in T}
[\max(0,0.02-u)]^2
}
\]

Properties:

- bits already safely positive receive no pressure;
- only the easiest current 24 bits matter;
- bit identity may change during optimization;
- the oracle does not waste distortion pushing all 32 bits;
- the verifier itself is unchanged and still only requires `K >= 24`.

`0.02` is an optimization buffer only.

It is **not** a new detector threshold.

# 17. Quality losses

For float oracle image \(x\) and float clean reference \(x^0\):

\[
L_{LPIPS}=LPIPS(x,x^0)
\]

\[
L_{pixel}=MSE(x,x^0).
\]

Also regularize the intervention energy.

For each tail call:

\[
E_t=
\frac{
\operatorname{mean}(\delta_t^2)
}{
\operatorname{mean}((\epsilon_t^0)^2)+10^{-8}
}.
\]

Define:

\[
L_\delta=\frac14\sum_t E_t.
\]

This makes residual energy relative to the natural scale of each cached guided prediction.

# 18. Adaptive feasibility-first objective

Do not use a large fixed fingerprint weight for every image.

Each image gets its own detector multiplier:

```text
w_det = 1.0 initially
```

Per-image objective:

\[
L_i
=
w_i L_{det,i}
+
L_{LPIPS,i}
+
L_{pixel,i}
+
0.01L_{\delta,i}.
\]

Every 20 optimization steps:

```text
20, 40, 60, 80, 100
```

if that image has never reached the float oracle criterion:

```text
K >= 24
and min(top24 signed margin) >= 0.02
```

then:

```text
w_det = min(2 * w_det, 32)
```

Once the image has reached the criterion at least once, stop increasing its `w_det`.

Do not lower `w_det`.

This avoids one arbitrary huge global fingerprint coefficient while still allowing difficult images to receive more detection pressure.

# 38. Unit tests

Add a dedicated oracle test file.

## 38.1 Zero-control exactness

With `delta = 0`, oracle replay must reproduce the cached clean final latent under the same scheduler replay tolerances.

A final detector loss must produce finite nonzero gradient to all four `delta_t` tensors.

## 38.3 No source gradients

No gradient to:

- cached boundary latent;
- cached tail outputs;
- carrier;
- VAE weights;
- semantic reference UNet;
- secret signs.

## 38.4 Dynamic top-24 behavior

Construct synthetic margins and verify:

- only current top24 are penalized;
- positive-safe bits receive zero loss;
- selection can change after margins change;

Verify STE forward output matches actual project PIL/PNG save-read values.

Do not silently use float K.

## 38.7 Best-candidate selection

1. LPIPS;
2. pixel MSE;
3. relative delta energy;
4. earlier step.

## 38.8 Source read-only test

Snapshot source hashes before oracle execution and assert unchanged afterward.

## 38.9 Resume

## 38.10 Finite guards

# 40. Important scientific limitation

This oracle is intentionally more powerful than a real model.

It gives every image its own four free residual tensors.

Therefore:

```text
oracle success != teacher success
```

Oracle success only establishes:

> A low-distortion control solution exists in the current final-tail control space for most images.

The later imprinting problem is:

> Can one shared teacher parameterization predict/generalize these controls from prompt/latent/timestep?

Keep this distinction explicit in code comments and reports.
